아래 입력은 중소기업 대표가 Claude Code로 자기 회사 업무 프로그램(ERP)을 만들며 나눈 대화 기록(JSONL)이다.
이 대화를 부스트온 '해결 기록' 초안 하나로 정리하라. 다른 대표들이 같은 고민을 만났을 때 참고하는 기록이다.

먼저 기록할 만한지 판단한다. 회사 일에서 부딪힌 문제(직원 반응, 현장 사정, 비용 걱정, 데이터 정리, 기존 시스템 연결, 보안 걱정, 시간 부족, 유지·관리)와 그걸 다룬 과정이 없고 단순한 코드 수정·질문뿐이면 아래만 출력한다.
{"skip": true}

기록할 만하면 아래 JSON 하나만 출력한다. 설명, 마크다운, 코드 블록 표시는 쓰지 않는다.
{
  "category": "staff | field | cost | data | connect | security | time | upkeep 중 하나",
  "title": "무슨 일이 있었는지 한 줄, 40자 안쪽",
  "situation": "그때 회사 사정과 걱정",
  "steps": [{"text": "한 일과 그 반응", "worked": true 또는 false 또는 null}],
  "result": "지금 어떻게 됐는지. 없으면 빈 문자열",
  "remaining": "아직 남은 문제. 없으면 빈 문자열",
  "cost": "",
  "duration": "걸린 기간. 모르면 빈 문자열",
  "status": "solved | partly | stuck"
}

반드시 지킬 것:
- '~했습니다'체. 대표가 직접 쓴 것처럼. 꾸미지 않는다. 안 통한 시도도 단계로 남긴다(worked: false).
- 대화에 없는 사실은 지어내지 않는다.
- 회사 정보를 쓰지 않는다:
  - 매출, 금액, 단가, 가격, 이익, 거래량, 고객 수, 직원 수, 수량 같은 숫자는 쓰지 않는다. "크게 줄었습니다", "여러 명"처럼 숫자 없이 쓴다. 걸린 시간(2시간 → 30분, 3주)만 숫자로 써도 된다.
  - 사람 실명은 쓰지 않는다. "반장님", "경리 직원", "영업 담당"처럼 직함으로.
  - 회사·거래처·고객·제품 이름을 쓰지 않는다. "거래처", "고객사", "주력 제품"으로.
  - 전화번호, 이메일, 주소, 주민번호, 계좌·카드번호, 비밀번호, API 키, 토큰, DB 주소는 쓰지 않는다.
- cost 칸은 비워 둔다.
